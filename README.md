# github-cli-nix

Always up-to-date Nix package for [GitHub CLI](https://github.com/cli/cli) (`gh`) — GitHub on the command line.

> **Beta**: This project is under active development by a solo maintainer and may break between updates. Use at your own risk. Contributions are welcome — feel free to open issues or submit pull requests!

## Why this package?

`gh` is already in nixpkgs, but the version there can lag behind upstream by days or weeks. This flake lets you:

1. **Get newer versions sooner** — update as soon as a compatible release drops
2. **Declarative installation** — managed in your NixOS or Home Manager config
3. **Reproducible builds** — built from source via `buildGoModule`

## Go floor

The Nix sandbox enforces `GOTOOLCHAIN=local`, so a `gh` tag is only buildable if its `go.mod` requirement is satisfied by the Go shipped in the **nixos stable** channel (what downstream consumers using `inputs.nixpkgs.follows` build with). This flake therefore tracks the latest upstream release that fits under that floor — usually simply the latest release.

> History: while `nixos-25.11` (Go 1.25.x) was stable, the flake was pinned to `v2.87.3` because `cli/cli` 2.88.0+ requires `go 1.26`. The pin was lifted in June 2026 when `nixos-26.05` (Go 1.26.3) became the stable channel. The autonomous `update.sh` is floor-aware and will re-pin automatically if upstream's Go requirement ever outruns stable again.

## Project Structure

| File | Purpose |
|---|---|
| `flake.nix` | Flake definition: inputs (nixpkgs, flake-utils), overlay, packages, app |
| `package.nix` | Build recipe: fetches the GitHub source, runs `make`, installs `gh`, manpages and shell completions |
| `default.nix` | Non-flake entry point (NUR-compatible) |
| `flake.lock` | Pinned inputs |
| `update.sh` | Autonomous update workflow driven by Claude Code |
| `.gitignore` | Excludes Nix build artifacts and editor files |

## Quick Start

```bash
# Run directly without installing
nix run github:selfhost-it/github-cli-nix

# Install to your profile
nix profile install github:selfhost-it/github-cli-nix
```

## NixOS / Home Manager Integration

### Add to your flake inputs

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

    github-cli = {
      url = "github:selfhost-it/github-cli-nix";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };
}
```

### Apply the overlay

```nix
{
  nixpkgs.overlays = [
    github-cli.overlays.default
  ];
}
```

### Add to your packages

NixOS (`configuration.nix`):

```nix
environment.systemPackages = with pkgs; [
  gh
];
```

Home Manager (`home.nix`):

```nix
home.packages = with pkgs; [
  gh
];
```

## Building Locally

```bash
git clone git@github.com:selfhost-it/github-cli-nix.git
cd github-cli-nix
nix build .

# Test
./result/bin/gh --version

# Or run directly
nix run .
```

## Updating to a new gh version

1. Change `version` in `package.nix` (e.g. `"2.92.0"`)

2. Set `hash = "";` in `package.nix` and run:
   ```bash
   nix build .
   ```
   The build will fail and print the correct hash. Paste it back.

3. Set `vendorHash = "";` in `package.nix` and run:
   ```bash
   nix build .
   ```
   Again, paste the hash from the error message.

4. Run `nix build .` again — it should succeed.

5. Verify with `./result/bin/gh --version` — the output **must** show the new version, not `DEV` (the latter would mean the `-ldflags` injection failed).

6. Commit and push.

The autonomous workflow `./update.sh` performs all of these steps using Claude Code.

## Technical Details

- **Source**: Built from the [cli/cli](https://github.com/cli/cli) GitHub repo
- **Builder**: `buildGoModule` driving the upstream `Makefile` (`make bin/gh manpages`)
- **Runtime**: statically-linked Go binary, no runtime dependencies
- **Binary**: `gh` (at `$out/bin/gh`)
- **Manpages**: installed under `$out/share/man/man1`
- **Shell completions**: bash, zsh and fish completions are generated by invoking `gh completion -s <shell>` against the freshly-built binary, then installed via `installShellCompletion`. This step is skipped when cross-compiling (the build host can't execute the target binary).
- **Version injection**: the upstream `Makefile` reads `GH_VERSION` and passes it to the linker via `-X github.com/cli/cli/v2/internal/build.Version=...`. This package sets `GH_VERSION=v${version}` so `gh --version` reports the correct tag.
